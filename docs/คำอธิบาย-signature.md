## อธิบายว่าเหตุใด Token ที่ถูกแก้ไขแม้เพียงตัวอักษรเดียวจึงถูกปฏิเสธ

### อ้างอิงจาก `wk06.md`

JWT ประกอบด้วย 3 ส่วน คั่นด้วยจุด (`.`) ในรูปแบบ

```text
Header.Payload.Signature
```

- **Header** ระบุอัลกอริทึมที่ใช้สร้าง Signature เช่น `HS256`
- **Payload** เก็บข้อมูลของผู้ใช้ เช่น `{"id": 1, "role": "student"}`
- **Signature** ถูกสร้างจาก Header + Payload + Secret Key เพื่อยืนยันว่า Token ไม่ถูกแก้ไข

---

### คำอธิบาย

แม้ JWT จะเป็นข้อความที่ดูเหมือนตัวอักษรสุ่ม แต่ส่วน Header และ Payload สามารถถอดออกมาอ่านข้อมูลได้ โดยเซิร์ฟเวอร์จะใช้ข้อมูลใน Header และ Payload ร่วมกับ Secret Key เพื่อสร้าง Signature สำหรับ Token นั้น

ดังนั้น หากมีการแก้ไข Token แม้เพียงตัวอักษรเดียว ข้อมูลใน Token ก็จะเปลี่ยนไป ทำให้ Signature เดิมไม่ตรงกับข้อมูลที่ถูกแก้ไข เมื่อเซิร์ฟเวอร์ตรวจสอบจึงรู้ว่า Token ถูกดัดแปลง และปฏิเสธการใช้งานทันที
